## Why this matters

Most teams discover multi-agent failure modes the same way: a critical demo,
a senior stakeholder, a confidently-wrong agent. The patterns below come from
shipping these systems into customer-facing flows where "model picked the
wrong tool" is a P1.

<PullQuote attribution="A senior staff engineer, after a long week">
  The hard part of multi-agent isn't the agents — it's the protocol they
  use to talk to each other.
</PullQuote>

## Three patterns that pay off

1. **Strict tool schemas with provenance.** Every tool call records which
   agent invoked it, with what arguments, and what came back. Replay
   becomes trivial; debugging stops being archeology.
2. **Bounded autonomy ladders.** Each agent has a maximum number of
   self-directed steps before control returns to a supervisor. This caps
   blast radius without sacrificing the value of agentic loops.
3. **Eval-as-deployment-gate.** A regression suite of real customer
   prompts, run on every model swap. If win-rate drops, the deploy
   doesn't ship.
